# アセットロック運用ガイド(.mb / .fbx / .abc)

`Assets/Designer/` 以下の Maya / FBX / Alembic ファイルを、Git LFS のロックで「作成者以外は編集できない」状態にする仕組み。
GitHub(クラウド)にはサーバー側で書き込みを物理的に止める仕組みが無いため、**クライアント側フック + LFS ロックによる疑似的な排他制御**である。

## 仕組み

| 構成要素 | 役割 |
|---|---|
| `.gitattributes` の `lockable` | 自分がロックしていない対象ファイルをチェックアウト時に read-only にする(うっかり編集の防止) |
| `.githooks/pre-commit` | コミット時にロックを確認。ロック無し → 自分名義で自動ロック / 他人のロック → コミット拒否 |
| Git LFS の `pre-push` | 他人がロック中のファイルを変更したコミットの push を拒否(`--no-verify` でコミットされた場合の二重チェック) |

- 対象: `Assets/Designer/**/*.{mb,fbx,FBX,abc}`
- ロックは**解除しない運用**。最初にコミットした人がそのファイルの担当者になる。
- マージコミットの完了時(`MERGE_HEAD` がある時)はチェックしない(他人の変更の取り込みのため)。
- ロック確認には GitHub への通信が必要。オフライン時は対象ファイルを含むコミットは失敗する。

## セットアップ(クローン後に1回)

Unity を開くと `Assets/Editor/Github/GitHooksSetup.cs` が自動設定する。
Unity を開かない人は `Tools/SetupGitHooks.bat` をダブルクリックするか、以下を実行する。

```bash
git config core.hooksPath .githooks
```

## 他人のロック中ファイルをコミットしようとした場合

GitHub Desktop の Commit failed ダイアログに以下が表示される。

```
エラー: ロック中のファイルが含まれています。

  Assets/Designer/Mesh/hero.fbx は alice によってロックされています

このファイルは作成者以外編集できません。担当を変更する場合は管理者に連絡してください。
```

変更を破棄する(GitHub Desktop で右クリック → Discard changes)か、下記の引き継ぎ手順を依頼する。

## ロック状況の確認

```bash
git lfs locks
```

## 担当変更・引き継ぎ(管理者のみ)

1. 引継ぎ元が未コミットの変更をすべて commit & push する。
2. 引継ぎ元が管理者に解除を依頼する。
3. 管理者(リポジトリの admin 権限者)が強制解除する。
   ```bash
   git lfs unlock --force "Assets/Designer/Mesh/hero.fbx"
   ```
4. 引継ぎ先がファイルを編集して commit する → pre-commit がロック無しを検知し、引継ぎ先の名義でロックを取得する。

管理者が他人の代わりにロックを取ることはできない(`git lfs lock` は実行者の認証情報で登録される)ため、必ず「管理者の解除」と「引継ぎ先のコミット」の2ステップになる。

## 既存ファイルへの初回ロック付与

フック導入前からあるファイルはロックが無い状態。**次にそのファイルを変更してコミットした人**が自動でロックを取得する。
担当者を明示したい場合は、担当者本人が以下を実行する。

```bash
git lfs lock "Assets/Designer/Mesh/xxx.fbx"
```

## 既知の制約

| 項目 | 状態 |
|---|---|
| `--no-verify` によるフックのバイパス | コミットは防げない(push は LFS の pre-push が拒否する) |
| サーバー側で内容ベースに push を拒否 | GitHub.com では不可。ブランチ保護で直接 push 禁止にはできる |
| 閲覧の禁止 | 不可(ロックは編集制御であり閲覧制限ではない) |
| force unlock の権限を無くす | 非推奨(退職者のロック放置対策の安全弁) |
