# リザルト遷移のネットワーク方針

MainScene(ゲーム本編)から ResultScene(リザルト)へ移動するときの、通信とスコアの受け渡しの方針です。
ネットワーク担当(秋野)が後で実装するときのための資料です。

- 決定日: 2026-10-06(ネットワーク担当: 秋野)
- 関連: Issue #177、[ClaudeDocs/スコアの使い方.md](../ClaudeDocs/スコアの使い方.md)、[ClaudeDocs/スコア・リザルトの修正ポイント.md](../ClaudeDocs/スコア・リザルトの修正ポイント.md)

## 結論: A案で進める

| 案 | 内容 | 採用 |
|---|---|---|
| **A** | ホストが`NetworkManager.SceneManager.LoadScene`で全員をまとめて移動させる | **採用** |
| B | ホストが全員に終了を通知 → 各自が保存してから通信を終了(`Shutdown`) → 各自で移動 | 不採用 |

## 現状(2026-10-06時点)

- 時間切れの判定は`CS_TimerController`が**サーバーだけ**で行い、サーバーだけが`CS_SceneTransitioner.StartTransition()`を呼ぶ
- `CS_SceneTransitioner`は`SceneManager.LoadScene`(**その端末だけ**が移動する)を使っている
  - → クライアントはMainSceneに残ったままになる
- `CS_TimerController`の時間切れ処理に、リザルトへの保存のTODOが残っている
- スコア(`CS_ResultData.Score`)はプレイヤーごとの`NetworkVariable`で**全クライアントに同期済み**
  - 全プレイヤー分は`CS_PlayerResultDataHolder.CollectResults()`で集められる(プレイヤー側で実装済み)

## やること

### 1. 移動はホストがまとめて行う(`CS_SceneTransitioner`)

- オンライン時: **ホスト(サーバー)だけ**が`NetworkManager.Singleton.SceneManager.LoadScene(シーン名, LoadSceneMode.Single)`を呼ぶ
  - クライアントはNetcodeのシーン同期で自動的に移動する(クライアントから呼んではいけない)
- オフライン時(テストシーン): 今まで通り`SceneManager.LoadScene`
- 前提: ResultSceneがBuild Settingsに入っていること(`NetworkSceneManager`はBuild Settingsのシーンしか読み込めない)
- 前提: NetworkManagerの`Enable Scene Management`がオンであること

```csharp
public void StartTransition()
{
    NetworkManager manager = NetworkManager.Singleton;
    if (manager != null && manager.IsListening)
    {
        // シーンの移動はサーバーだけが行う(クライアントは自動で付いてくる)
        if (!manager.IsServer) return;

        manager.SceneManager.LoadScene(_nextSceneName, LoadSceneMode.Single);
        return;
    }

    // オフライン(テストシーン)
    SceneManager.LoadScene(_nextSceneName);
}
```

### 2. 保存は全員が「移動が始まる前」に自分で行う

- 保存する1行: `CS_ResultDataStore.Save(CS_PlayerResultDataHolder.CollectResults());`
- スコアは同期済みなので、**各端末が自分の手元のプレイヤー全員分を集めて保存すれば足りる**(保存のためのRPCは不要)
- **タイミングは`NetworkManager.SceneManager.OnSceneEvent`で、移動が始まった時(`SceneEventType.Load`)に保存する**
  - 移動するとMainSceneのプレイヤー(とスコア)が消えるため、必ずその前に保存する
  - タイマーの残り時間(0になったら)で保存しない理由: クライアントの`ServerTime`はホストより少し遅れて進むので、
    クライアントが0になる前にホストの移動が届き、保存する前にプレイヤーが消えることがある

```csharp
// 例: MainSceneにいる間だけ購読する(購読する場所はタイマーなど、MainSceneに1つだけあるもの)
private void HandleSceneEvent(SceneEvent sceneEvent)
{
    // 移動の開始(ホスト・クライアントの全員に届く)。この時点ではまだプレイヤーが残っている
    if (sceneEvent.SceneEventType != SceneEventType.Load) return;
    if (sceneEvent.SceneName != _resultSceneName) return;

    CS_ResultDataStore.Save(CS_PlayerResultDataHolder.CollectResults());
}
```

- ※ `OnSceneEvent`のイベントは、届く端末(`sceneEvent.ClientId`)ごとに来ることがある。自分の端末の分だけで保存すれば十分(何度保存しても同じ内容なので、複数回呼ばれても問題は無い)
- オフライン時は、`StartTransition()`の直前に保存する

## 未決事項

- **リザルトの後、タイトル・ロビーへ戻るときの通信の扱い**
  - A案ではResultSceneの時点ではまだ通信がつながっている
  - 戻るときに`Shutdown`して各自で移動するのか、つないだままロビーへまとめて移動するのかを決める
  - NetworkManagerがDontDestroyOnLoadで残るため、タイトルへ戻って再接続する場合は`Shutdown`が必要
- **途中で切断したプレイヤーのスコア**: 切断するとそのプレイヤーのオブジェクトが消えるため、リザルトに出ない(出すなら切断時に控えておく仕組みが必要)
- **NPC**: NPCもプレイヤーと同じ`CS_PlayerResultDataHolder`を持つので、同じ方法でリザルトに含まれる
