# プレイヤーの見た目の差し替えガイド

プレイヤーの見た目(モデル・アニメーション)は、ゲームロジックから完全に分離されています。本番アセットが来たら、以下の手順で差し替えられます。**C#の変更は基本的に不要**です。

## 仕組み

```
CS_Player / CS_PlayerAttack / CS_PlayerSpecialAttack / CS_PlayerHealth
        │ 状態(isGrounded, isDead …)とイベント(onJumped, onStepStarted …)
        ▼
CS_PlayerVisual ── Animatorのパラメータを更新 ──▶ Animator Controller ──▶ モデル
```

- ゲームロジック側は`CS_PlayerVisual`を知らない(外してもゲームは動く)
- `CS_PlayerVisual`はAnimatorを子オブジェクトから自動で探す(`_animator`が空でも可)
- Animator Controllerに**存在しないパラメータは無視される**。全部揃っていなくてよい
- 見た目は子の`Model`(`CS_PlayerVisual`の`Animator`欄)の1つだけ。常時変身(Issue #277)になったため、以前あった通常の見た目との切り替えと、変身途中のエフェクトは削除した
  - 現在のモデル: Munnki(`Assets/Programmer/PlaceholderAsset/Player/Munnki/Model/FBX/Munkki_mixamo_rigged.fbx`)
    - Rigは**Humanoid**(Mixamoのボーン。Humanoidのモーションならそのまま使い回せる)
    - 大きさは当たり判定のカプセル(高さ2m)に合わせ、`Model`のScaleを約1.3倍(元は約1.54m)にしている
    - 足元を合わせるため、`Model`のローカルYは約-0.864(靴底がモデルの原点より約0.1m(拡大後は約0.136m)下にあるため)
    - マテリアルは`Munnki/Model/Material/`(HDRP/Lit)。FBXのマテリアル設定(Remap)で割り当てている
  - Animator Controller: `Munnki/Animation/PlayerMunnkiAnimator.controller`(以前の仮Controllerを複製して、**モーションだけ空にしたもの**)

## モーションの追加手順(Munnki)

`PlayerMunnkiAnimator.controller`には状態・遷移・パラメータが揃っていて、モーション欄には仮の立ちポーズ(`Munnki/Animation/Munnki_TPose.anim`、モデルの元のT-ポーズ)が入っています。モーションを入れ替えた状態から順に動くようになります。

※ Humanoidはモーションが空だと腰がモデルの原点(足元)まで下がり、地面にめり込みます。仮の立ちポーズはそれを防ぐためのものなので、**モーションが無い状態は空にせず仮の立ちポーズのままにしておく**。全部入れ替えたら`Munnki_TPose.anim`は削除してよい

1. モーションのFBXをインポートし、Rigを**Humanoid**、Avatar Definitionを`Copy From Other Avatar`にして`Munkki_mixamo_riggedAvatar`を指定する(Mixamoから落とす場合は「Without Skin」でよい)
2. ループさせるモーション(待機・移動・空中)は、FBXのAnimationタブで`Loop Time`をオンにする
3. `PlayerMunnkiAnimator.controller`を開き、各状態の`Motion`欄の`Munnki_TPose`を新しいモーションに入れ替える

| 状態 | 入れるモーション |
|---|---|
| `Locomotion` | ブレンドツリー(`MoveX`/`MoveZ`)。中央=待機、上=前進、下=後退、左=左移動、右=右移動 |
| `JumpStart` / `Air` / `JumpLand` | ジャンプの開始 / 空中 / 着地 |
| `Dash` | ダッシュ |
| `Attack1`〜`Attack3` | 通常攻撃の1〜3段目(4・5段目は先頭から使い回す。`CS_PlayerVisual`の`Attack Motion Count`) |
| `Special` | 必殺技 |
| `Hit` | 被弾 |
| `Death` | 死亡 |

4. 本物のモーションを入れた後、足が地面から浮いたりめり込んだりしていたら、`Model`のローカルYで合わせる
5. 攻撃・必殺技・ダッシュは、状態の`Speed`でモーションの長さを`CSO_AttackData`の`Duration`(ダッシュは`CS_Player`の`Dash Duration`)に合わせる(今は1)

## Animatorパラメータ(コードとの約束)

定義: [`CS_PlayerAnimatorParams.cs`](../Assets/Programmer/Script/Entity/Player/CS_PlayerAnimatorParams.cs)

| 名前 | 型 | 内容 |
|---|---|---|
| `Speed` | float 0〜1 | 移動の速さ(通常移動速度で割った値) |
| `MoveX` | float -1〜1 | 体から見た左右の移動(右が+) |
| `MoveZ` | float -1〜1 | 体から見た前後の移動(前が+) |
| `Grounded` | bool | 接地しているか |
| `Dead` | bool | 死亡中か |
| `Jump` | trigger | ジャンプした瞬間 |
| `Dash` | trigger | ダッシュ開始の瞬間 |
| `Attack` | trigger | 通常攻撃の各段の開始(直前に`ComboStep`がセットされる) |
| `ComboStep` | int | 何段目か(0始まり) |
| `Special` | trigger | 必殺技の開始 |
| `Hit` | trigger | HPが減った(死亡時を除く) |

## 差し替え手順

1. 新しいモデルをインポートする(Humanoidを推奨。アニメーションを使い回せる)
2. `Player.prefab`を開き、子の`Model`を新しいモデルのプレハブに入れ替える
   - 足元がカプセルの底(ローカルY = -1)に来るようにする
   - モデルに`Animator`が付いていること
3. 新しいAnimator Controllerを作り、上の表のパラメータで遷移を組む(既存の`PlayerMunnkiAnimator.controller`を複製して、モーションだけ差し替えるのが早い)
4. `Model`の`Animator`にControllerを割り当てる
5. `CS_PlayerVisual`の`Animator`欄が新しい`Model`のAnimatorを指しているか確認(自動検索されるので空でも可)
6. `Tools/Player/仮の見た目を組み込む`は**もう実行しない**(実行すると仮アセットに戻る)。不要になったら`Assets/Editor/Player/CSED_PlayerTempVisualBuilder.cs`と`Assets/Programmer/PlaceholderAsset/Generated`のプレイヤー用アセットを削除してよい

## 注意点

- **ルートモーションは使わない**(移動はRigidbodyが行う。`CS_PlayerVisual`が強制的にオフにする)
- 攻撃の長さ・判定タイミングは`CSO_AttackData`(`Duration`、`Hit Delay`)が決める。モーション側をそれに合わせる(以前のMannequin用の仮Controllerは再生速度をDurationに自動調整していた。Munnkiでは手で合わせる)。段数を増やす場合は`Attack Steps`と`ComboStep`の遷移を増やす
- 攻撃・ジャンプ・ダッシュ・必殺技の再生は「操作している本人が再生+RPCで他クライアントへ通知」。途中参加のクライアントには過去の単発動作は再生されない(死亡は状態から判定するので反映される)
- アイテム使用のモーションは未対応(`CS_PlayerItemSlot`の所持状態がサーバー側にしかないため。対応するときはスロットの同期とセットで行う)
- 新しい動作(例: しゃがみ)を足すときは、ゲームロジック側にイベントを追加し、`CS_PlayerVisual`の`ActionType`とパラメータを増やす
