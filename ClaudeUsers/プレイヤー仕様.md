# プレイヤー仕様(実装済み機能の一覧)

このドキュメントは、`Assets/Programmer/Prefab/Entity/Player/Player.prefab` の現在の実装内容をまとめた資料です。
プレイヤー関連の機能を追加・修正する担当者(とそのClaude)向けの引き継ぎ資料として使ってください。

関連ドキュメント: [ItemSlot実装ガイド](ItemSlot実装ガイド.md)(アイテム側の設計。プレイヤー側は実装済み)

ボタン(`attackAction`など)は`CS_PlayerButton`で公開しており、人の時は`InputAction`を、NPCの時は判断(`CS_PlayerNpcBrain`)が押したボタンを返します。各コンポーネントは人かNPCかを気にせず`WasPressedThisFrame()` / `IsPressed()`で読むだけです。

**「自分の画面のプレイヤーか」は`IsOwner`ではなく`CS_Player.isLocalPlayer`で判定してください。** NPCはサーバーが所有するため、ホストではNPCも`IsOwner`がtrueになります(HUD・ミニマップ・頭上順位・カメラの揺れは対応済み)。

## ステータス: `CS_PlayerStats`

**プレイヤーに影響する数値変更は、すべてこのコンポーネントを通します。** バフ・デバフ・装備効果などを実装する際は、他のコンポーネントを直接触らずここを経由してください。

| ステータス | 読み取り | 変更 | 用途 |
|---|---|---|---|
| HP上限 | `maxHp` | `SetMaxHp(value)` | `CS_PlayerHealth`が参照。上限が下がると現在HPも自動でクランプされる |
| 攻撃力(倍率) | `attackPower` | `SetAttackPower(value)` | `CS_PlayerAttack`のダメージに掛かる(既定 1 = 等倍) |
| 移動速度 | `moveSpeed` | `SetMoveSpeed(value)` | `CS_Player`の通常移動で使用 |
| ジャンプ力 | `jumpPower` | `SetJumpPower(value)` | `CS_Player`のジャンプ初速 |
| ダッシュ速度 | `dashSpeed` | `SetDashSpeed(value)` | `CS_Player`のダッシュ中の速度 |
| スプリント速度 | `sprintSpeed` | `SetSprintSpeed(value)` | `CS_Player`の「ダッシュ後、ダッシュボタンを押し続けている間」の速度(`moveSpeed`より速く`dashSpeed`より遅い想定) |
| 必殺ゲージ上限 | `maxGauge` | `SetMaxGauge(value)` | `CS_PlayerSpecialGauge`が参照。上限が下がると現在値も自動でクランプされる |
| 必殺ゲージ現在値 | `currentGauge` | (直接変更不可) | 実体は`CS_PlayerSpecialGauge`。溜める/消費するには`CS_PlayerSpecialGauge.Fill()` / `TryConsumeFull()`を使う |
| 必殺技威力(倍率) | `specialAttackPower` | `SetSpecialAttackPower(value)` | `CS_PlayerSpecialAttack`のダメージに掛かる(`attackPower`とは別枠、既定 1 = 等倍) |

- 起動時は`Base Stats`(`CSO_PlayerStats`、実体は`Assets/Programmer/Database/Player/DB_PlayerStats.asset`)の値で初期化される
- `ResetToBase()`で全ステータスを基準値に戻せる(リスポーン等で使う想定)
- 値は`NetworkVariable`(書き込みはサーバーのみ、読み取りは全員可)。`SetXxx`系メソッドはサーバー以外から呼んでも無視される
- `onXxxChanged`イベント(例: `onAttackPowerChanged`)がHUD表示用に用意されている

**デバフの実装例**(一時的に攻撃力を下げる場合):

```csharp
float original = stats.attackPower;
stats.SetAttackPower(original * 0.5f);
// ...時間経過...
stats.SetAttackPower(original);
```

> 複数のバフ・デバフが同時に重なる仕様になった場合、上記の「元の値を覚えて戻す」方式では不整合が起きやすくなります。そのタイミングで倍率をリスト管理する仕組みへの拡張を検討してください。

## 移動・カメラ: `CS_Player`

- 三人称視点。`Rigidbody`で物理的に動く(`CharacterController`は使用していない)
- **体の向き**: カメラを回しただけでは体は回らない。**移動キーを押している間だけ**、進む方向(カメラから見た入力の方向)へ体を回転させる(`_rotationSpeed`、既定720度/秒)。止まっている間はカメラだけ自由に回せる
  - 仕様書「カメラについて」は「カメラを左右に回すとプレイヤーキャラの向きも変わるようにしたい」だが、手触りの調整で変更した(2026-10-15)
  - 例外: エイムアシスト中は攻撃する相手の方、ダッシュ中はダッシュの方向を向く。NPCは止まっている間も、判断が指定した向きへ回る(相手の方を向いて待つ・攻撃するため)
  - 首だけ先に曲げて体が遅れて追従する、といった演出(+α案)は未実装
- **移動の考え方**: 押した方向(カメラ基準)へ**すぐに**移動を始め、体の向きは回りながら追いつく(以前は体がカメラの向きに30°以内まで向くまで動かなかったが、振り返る時に一瞬止まるため廃止)
- 操作は「自分が操作するプレイヤー」のみ行う(`isControlled`)。死亡中は`canAct`が`false`になり、移動・ジャンプ・ダッシュ・攻撃を行わない(**視点操作だけは死亡中も継続**する)
- カメラはプレイヤーの子だが、揺れを防ぐため`LateUpdate`で毎フレーム位置・回転を直接計算して配置している
- カメラには`CinemachineBrain`が付いている。`CS_Player`は実際のカメラではなく、子の`PlayerVirtualCamera`(`CinemachineCamera`)の位置・向きを毎フレーム指定し、Brainがそれをカメラへ反映する(他人のプレイヤーの`PlayerVirtualCamera`は無効化する。残すと自分のBrainが他人のカメラを選んでしまうため)
- **攻撃時のカメラの揺れ**(仕様「当てられた or 当てた時に画面を揺らす」): `CS_PlayerCameraShake`が`CinemachineImpulseSource`で揺れを発生させ、`PlayerVirtualCamera`の`CinemachineImpulseListener`が受け取る。強さは**攻撃ごと**に`CSO_AttackData`の`Camera Shake Force`で決める(0で揺れない。現状は通常攻撃 0.1/0.1/0.15、必殺技 0.4。仮の値)。揺れ方(長さ・形)は`Player`の`CinemachineImpulseSource`、全体の強さの一括調整は`CinemachineImpulseListener`のGainで変える。自分のカメラだけが揺れる
  - **当てた時**: 判定が出る瞬間に、手元で同じ範囲に相手がいるか確かめ、いた時だけ揺らす(空振りでは揺れない。実際のダメージ判定はサーバー)
  - **当てられた時**: 自分のHPが減った時に`Damaged Shake Force`(既定0.3、仮の値)で揺らす。回復・復活では揺れない
- カメラの上下角度(ピッチ)は`_minPitch`(既定-15°)〜`_maxPitch`(既定60°)の範囲に制限される
- 処理順序: `Update`(入力読み取り・視点更新) → `FixedUpdate`(回転・移動・ジャンプ・ダッシュ) → `LateUpdate`(カメラ配置)

## ジャンプ

- `CapsuleCollider`の底から下方向にレイを飛ばして接地判定(`_groundLayers`で判定するレイヤーを指定。既定は全レイヤー)
- 接地中にジャンプボタンを押すと、`CS_PlayerStats.jumpPower`を初速として真上に飛ぶ
- 入力は`Update`で検知して予約し、実際に飛ぶ処理は`FixedUpdate`内の`Move()`の後に行う(`Move()`が毎回Y速度を保持したまま上書きするため)
- 長押しによる強ジャンプなどは未実装(「とりあえず通常ジャンプのみ」という仕様のため)

## ダッシュ(ブリンク)・スプリント

- 移動入力があればその方向、無ければ現在向いている方向へ、`CS_PlayerStats.dashSpeed`で一定時間(`_dashDuration`、既定0.2秒)だけ直進する(社内では瞬間移動的な挙動という意味で「ブリンク」とも呼ぶ)
  - `dashSpeed`は`moveSpeed`の1.5倍(データ表の倍率: 通常移動速度1 / ダッシュ時速度1.5)。現状は`moveSpeed 8`(手触りで調整済みの値)に合わせて`dashSpeed 12`、`sprintSpeed 10`(`moveSpeed` < `sprintSpeed` < `dashSpeed`の順を保つ。スプリントはデータ表に無い項目)
  - `moveSpeed`を変える時は、`dashSpeed`も1.5倍に合わせること(仕様データ同期ツールで取り込むと、倍率×5で 移動5 / ダッシュ7.5 になる)
- クールタイム(`_dashCooldown`、既定0.8秒)の間は再発動できない
- ダッシュ中は通常の`Move()`・`ApplyJump()`を行わず、速度を直接指定する(「慣性は少なめできびきび動く」という要望に合わせたもの)
- 攻撃・必殺技とは排他制御していない(ダッシュキャンセルのような使い方が可能)
- **スプリント**: ダッシュが終わった後もダッシュボタンを押し続けている間は、`Move()`が参照する速度を`moveSpeed`から`sprintSpeed`に切り替えて移動する(ZZZのような「ブリンク後、ボタン長押しで速く走り続ける」挙動)。クールタイムとは無関係で、ボタンを離すと即座に通常速度へ戻る。`CS_Player.isSprinting`で状態を公開している(見た目用)
- **スピード感の演出(カメラのFOV)**: `CS_PlayerCameraFov`が、元のFOV(`PlayerVirtualCamera`のLens、既定60°)に足して広げる。**ブリンク中もスプリント中も同じ広さ**(+15°、`Dash Fov Add`)。ブリンクで素早く広がり(`Widen Speed`)、スプリントを続けている間はそのまま保ち、終わると元へゆっくり戻る(`Return Speed`)。スプリントは動いている時だけ。広さ・変わる速さはInspectorで調整できる。自分の画面のカメラだけを変える

## 通常攻撃: `CS_PlayerAttack`(3段コンボ)

- 攻撃ボタンで1段目 → 押し続けると2段目 → 3段目と派生。攻撃モーション中に押したボタンは先行入力として覚え、モーション終了と同時に自動で派生する
- 各段のデータは`CSO_AttackData`(ScriptableObject)で管理。**コードを触らず数値調整できる**
  - 実体: `Assets/Programmer/Database/Attack/DB_PlayerAttack1〜3.asset`
  - パラメータ: `damage`(威力) / `hitDelay`(判定発生までの秒数) / `duration`(モーション長) / `comboWindow`(次の段への受付時間) / `hitRange`・`hitRadius`(判定範囲) / `gaugeGain`(ヒット時に溜まる必殺ゲージ量。仕様に合わせプレイヤーの攻撃は0) / `cameraShakeForce`(判定が出る瞬間のカメラの揺れの強さ、0で揺れない)
  - 現状は3段とも`damage: 1`で統一している(仕様「ダメージ値は同じ」)。段差を付けたい場合は各アセットの`Damage`を変更するだけでよい
- **段ごとにユニークな処理を追加したい場合**、`CSO_AttackData`を継承し`CalculateDamage` / `OnHit`をoverrideした新しいScriptableObjectを作る(例はファイル冒頭コメント参照)
- 判定は正面`hitRange`先に出る、半径`hitRadius`の球状の範囲(`Target Layers`で判定対象を指定。現状は`Everything`)。当たった相手の`IDamageable.TakeDamage`をサーバー側で呼ぶ(オフラインのテストシーンではその場で実行)
  - 判定は、攻撃した本人の手元の位置・向きを`HitRpc`でサーバーへ送って行う(エイムアシストで補正した向き・踏み込んだ位置のまま当たるように。NetworkTransformの同期の遅れでずれないように)。送られてきた位置がサーバー上の位置から3m以上離れていたら信用せず、サーバー上の位置・向きを使う(`CS_AttackHitDetector.ResolvePose`)
- 実際のダメージ = `CalculateDamage()` × `CS_PlayerStats.attackPower`
- ヒットしても必殺ゲージは溜まらない(下記「必殺ゲージが溜まる要因」参照)
- **攻撃ボタンはインタラクトと共有**。操作できるもの(ケアパッケージなど)の近く・操作中は攻撃を出さない(`CS_PlayerInteractor.hasInteractTarget` / `isInteracting`を参照)
- 必殺技を行っている間は通常攻撃できない(`CS_PlayerSpecialAttack.isPerformingSpecial`を参照)
- **変身完了中でないと発動できない**(`CS_PlayerTransformation.isTransformed`を参照)。攻撃中は`CS_PlayerTransformation`側で変身解除を受け付けないため、コンボの途中で変身が解けることは基本的に無い(死亡時の強制解除を除く。その場合は判定タイミングの再確認で不発になる)

## エイムアシスト: `CS_PlayerAimAssist`

狙いが多少ずれていてもストレスなく攻撃が当たるよう、近くの敵へ自動で向きを補正する(仕様書「操作について」の「誰でも遊べるように」)。すべてInspectorで調整できる。

- 攻撃(各段)・必殺技の**開始時**に、`Range`(既定4m)以内・狙っている方向(カメラの向き)から左右`Angle`(既定75°)以内の敵を探し、近さと角度で一番狙いやすい1体を選ぶ(`Angle Priority`で角度をどれだけ重視するか)。いなければ何もしない(いつも通りカメラの向きで攻撃)
- 選んだ相手の方へすぐに体を向け(`CS_Player.SetAimFacing`)、**判定が出るまで相手を追って向き続ける**。判定が出てから`Facing Hold Time`(既定0.1秒)後に補正をやめ、体はカメラの向きへ戻る
- 攻撃が届かない距離なら、判定が出るまでに届く距離まで**踏み込む**(`CS_Player.Lunge`。最大`Max Lunge Distance`、既定1.5m。0で踏み込まない)。通常攻撃は判定の球の中心が相手に重なる距離まで、必殺技(自分中心)は範囲の半分の距離まで。ダッシュを始めると踏み込みは打ち切られる
- **悪人を優先**して補正する。範囲内に悪人が1体でもいれば悪人の中から選び、悪人がいない時だけ他のプレイヤー(人・NPC)を補正する(フレンドリーファイアは常に有効。悪人と戦っている最中に、近くの味方の方へ勝手に向かないように)。`Target Players`をオフにするとプレイヤーは補正しない。警察は倒せないので対象外
- 補正が終わった後、体は相手の方を向いたまま。移動キーを押すと進む方向へ回る(補正中も移動は止まらない)
- 攻撃している本人の手元でだけ動く(攻撃の開始イベントは本人の手元でしか発生しない)。`Is Assist Enabled`をオフにすると使わない

## 必殺技: `CS_PlayerSpecialGauge` / `CS_PlayerSpecialAttack`

- **変身完了中**かつ必殺ゲージが**満タンの時だけ**発動できる、単発の技(変身は下記「変身」を参照)
- データは`CSO_AttackData`を流用(通常攻撃と同じクラス)。実体: `Assets/Programmer/Database/Attack/DB_PlayerSpecial.asset`
- 発動すると`hitDelay`秒後に判定が出て、その瞬間に**サーバー側が改めて変身中かつ満タンか確認してから消費**する(先出し後に条件が変わっていた場合は不発。ゲージも消費しない)
- ダメージ = `CalculateDamage()` × `CS_PlayerStats.specialAttackPower`(通常攻撃の`attackPower`とは別枠、既定5)
- **判定範囲は自分を中心にした全方位**(`hitRange: 0`、`hitRadius: 3`)。通常攻撃と違って正面限定ではなく、周囲の悪人にまとめて当たる(`CS_AttackHitDetector`は`hitRange`が0だと自分の位置を中心に判定するため、コード側の変更は不要でアセットの数値だけで対応している)
- 通常攻撃・必殺技はどちらも変身完了中しか出せないため、実質「攻撃できるのは変身中だけ」という仕様になっている。通常攻撃と必殺技自体も排他制御されており、同時には出せない

### 必殺ゲージが溜まる要因(`CS_PlayerSpecialGauge`)

すべてInspectorで数値調整可能。

| 要因 | 既定値 | 備考 |
|---|---|---|
| 時間経過 | 毎秒1 | `_gaugePerSecond`。生きているかどうかに関わらず常に溜まる |
| 悪人の撃退 | 1体につき10 | `_villainDefeatGaugeGain`。**倒した本人だけ**に加算する(`CS_PlayerScoring.onVillainDefeated`を購読。スコアと同じく、通常攻撃・必殺技で倒した分が対象で、アイテムで倒した分は溜まらない) |

- 仕様(「時間経過と、悪人を倒すことでゲージが溜まっていく」)に合わせ、**通常攻撃のヒットでは溜めない**(`DB_PlayerAttack1〜3`の`Gauge Gain`を0にしている。仕組み自体は残っているので、数値を入れれば復活する)
- 上限(`maxGauge`)は既定240(`DB_PlayerStats`)
- 必殺技自体はゲージを増やさない(`DB_PlayerSpecial`の`gaugeGain`は0)

## 変身: `CS_PlayerTransformation`

- 状態は **通常 → 変身途中 → 変身完了** の3段階(`CSE_PlayerTransformState`)
- 変身ボタン(キーボード: Q / コントローラー: Rスティック押し込み)で変身を始め、`_transformDuration`秒(既定5秒、Inspectorで調整可能)で変身が完了する。変身完了中にもう一度押すと解除する
- **変身途中は無敵**(`CS_PlayerHealth.SetInvincible`でダメージを受けなくなる)。変身途中は解除できない
- 変身・解除は移動を止めない(移動しながら変身できる)
- **解除してから再変身までクールタイムがある**(`_cooldown`、既定5秒。Inspectorで調整可能)
- タグは変身が完了した時に切り替わる(変身途中はまだ通常のタグ)
  - 通常・変身途中: `PlayerNoTransformation` / 変身完了: `PlayerTransformation`(プレハブの初期タグは`PlayerNoTransformation`)
- 変身が完了していないと必殺技を使えない(`CS_PlayerSpecialAttack`が`isTransformed`を参照)
- **変身完了中は、一定間隔で現在地を警察へ知らせる。間隔は変身を続けるほど短くなる**(#155、仕様書「変形のリスク」)
  | 項目(Inspector) | データ表の項目名 | 既定値 |
  |---|---|---|
  | `Police Notify Interval` | 初期信号間隔 | 10秒 |
  | `Police Notify Shorten Time` | 間隔短縮時間 | 20秒 |
  | `Police Notify Shorten Amount` | 短縮時間 | 2秒 |
  | `Police Notify Min Interval` | (最短間隔。データ表に無く、プランナーに確認中の仮) | 2秒 |
  - 例: 変身完了から0〜20秒は10秒おき → 20〜40秒は8秒おき → 40〜60秒は6秒おき…(最短間隔より短くはならない)
  - 次の信号までの間隔は、信号を出した時点の経過時間で決まる。解除して再変身すると、また初期信号間隔から始まる
  - `CS_PoliceSquad.NotifyIncident(位置, 自分のCS_PlayerHealth)`を使う。現在地を警備エリアに含むグループのメンバーが`CS_PoliceBrain.RequestRush`で駆け付ける(エリア外なら誰も来ない)。あわせて、**このプレイヤーの手配度で出現した増援**も信号の場所へ駆け付ける(誰が出した信号かを警察側が判断するため、プレイヤーも渡している)
  - 変身が完了した瞬間そのものは、警察側(`CS_PoliceTransformationWatcher`)がタグの変化で検知して駆け付ける
- 死亡すると自動で解除される(解除扱いなのでクールタイムも始まる)
- **通常攻撃・必殺技を行っている間は解除できない**(判定の途中で解除されて不発になるのを防ぐため。`CS_PlayerAttack.isAttacking` / `CS_PlayerSpecialAttack.isPerformingSpecial`を参照)
- 通信: 状態・変身完了時刻・クールタイム終了時刻は`NetworkVariable`(書き込みはサーバーのみ)。Ownerがボタンを押す → RPCでサーバーに依頼 → サーバーが条件を確認して確定 → 全クライアントでタグが切り替わる。変身の完了と警察への通知もサーバーが行う。途中参加したクライアントもスポーン時に現在の状態のタグへ合わせる
- HUD・見た目向けに`state` / `isTransforming` / `isTransformed` / `transformRemaining`(変身完了までの残り秒数) / `cooldownRemaining`(再変身までの残り秒数) / `onStateChanged`イベントを公開している
- 変身が完了している間は、見た目が変身後のモデル(仮: `Mannequin_Large`)に切り替わる(`CS_PlayerVisual`が担当。差し替えは[プレイヤー見た目の差し替えガイド](プレイヤー見た目の差し替えガイド.md)を参照)
- 変身途中は足元から光の粒(パーティクル)が立ち上る(仮素材。`CS_PlayerVisual`の`Transforming Effect`欄で差し替え可能)

## 手配度: `CS_PlayerWantedLevel`

仕様は警察仕様書「手配度」(Issue #158)。手配度は**プレイヤーごと**に持つ(全員で共有しない)。

- 範囲: 0〜`Max Level`(仮で5)
- **上がる**
  - 変身を続けて、警察への信号の間隔が短くなるたびに+1(`CS_PlayerTransformation.onPoliceNotifyIntervalShortened`)
    - データ表の値だと: 変身完了 → 0 / 20秒後(8秒間隔) → 1 / 40秒後(6秒間隔) → 2 …
    - 間隔が最短間隔に達した後は、それ以上短くならないので上がらない
  - どこかの悪人グループが犯罪を完遂した時、**全プレイヤー**が`Crime Completed Increase`(仮で1。プランナーに確認中)上がる
- **下がる**
  - 変身を解く・死亡すると、`Decrease Interval`秒(既定2秒)ごとに1つ下がる(リスポーンの10秒で必ず0になる)
  - 下がっている途中でもう一度変身を始めたら、下がるのを止める
- 手配度は`NetworkVariable`で同期(書き込みはサーバーのみ)。増減の判断はサーバーだけが行う
- `onLevelChanged`(全クライアントで発生)を、警察の変化(#159)・追加スポーン(#160)・UIから購読して使う
- 手配度によって警察がどう変わるかは警察側で実装する(このコンポーネントは増減と通知だけ)
- **警察との連携**: プレイヤー側は「起きたことをイベントで知らせるだけ」で、受け取って警察を動かすのは警察側(宇留野さん)
  - `CS_PlayerWantedLevel.activePlayers`(出現中の一覧)と、static イベント `onAnySpawned` / `onAnyDespawned`(出現・消滅)
    - 出現: オンラインは `OnNetworkSpawn`、オフラインは `Start` / 消滅: `OnNetworkDespawn` または `OnDestroy`(リスポーンは出現・消滅にならない)
  - `CS_PlayerTransformation.onPoliceNotified`(信号を出した位置。サーバー、またはオフラインのみ)
    - 警察を動かす本体は `CS_PoliceSquad.NotifyIncident(位置, 自分のCS_PlayerHealth)` の呼び出し(警察側からの依頼で、信号を出したプレイヤーも渡している)
  - 手配度の値は、警察側がシーン内の `CS_PlayerWantedLevel` を探して `onLevelChanged` を購読する(プレイヤー側からは何も渡さない)

## HP・死亡: `CS_PlayerHealth`

- `IDamageable`を実装。`CS_PlayerAttack` / `CS_PlayerSpecialAttack`から`TakeDamage`が呼ばれる
- **現在HPは、HP上限(`CS_PlayerStats.maxHp`)が初めて有効な値になった時に満タンで始める**。`OnNetworkSpawn`の呼ばれる順(`Player.prefab`のコンポーネントの並び順)によっては、まだHP上限が0のことがあるため、その時はHP上限が入った時(`onMaxHpChanged`)に初期化する。以前は並び順のせいでHP0のまま始まり、1回死ぬまでHP表示がおかしかった(Issue #223)
- HPが0になると死亡状態(`isDead`)になり、移動・ジャンプ・ダッシュ・攻撃・必殺技ができなくなる(視点操作のみ継続)
- 無敵中はダメージを受けない。無敵は要因(呼び出し元)ごとに`SetInvincible(要因, true/false)`で管理し、1つでも要因が残っていれば無敵(ある要因の終了が他の要因の無敵を解除しない)
  - 現在の要因: 変身途中(`CS_PlayerTransformation`) / 復活直後(`CS_PlayerRespawn`) / **被弾直後(`CS_PlayerHealth`自身)**
  - **被弾すると(致死でなければ)`_postDamageInvincibleDuration`秒(既定3秒、Inspectorで調整可能)無敵になる**。無敵中は追加のダメージを受けないため、この無敵自体が連続ヒットで再スタートすることはない
  - 無敵の状態はサーバー側だけが持つ(ダメージ処理がサーバーだけで行われるため)
- **フレンドリーファイアは常に有効**(味方かどうかの区別はしておらず、`IDamageable`を実装していれば誰にでも当たる)
- `onHpChanged` / `onDeath`イベントをHUD・リスポーン処理向けに用意
- 死亡中は水平方向の速度を止める(空中で死んだ場合は真下に落ちる。死亡時の勢いで滑り続けない)
- `Revive()`でHPを全回復して復帰できる(`CS_PlayerRespawn`が呼ぶ)

## 復活: `CS_PlayerRespawn`

- 死亡してから`_respawnDelay`秒(既定10秒、Inspectorで調整可能)後に、**死んだ場所で**HP満タンで復活する(位置は動かさない。空中で死んだ場合は落下して止まった位置)
- 復活の処理はサーバーで行う(`CS_PlayerHealth.Revive()`がサーバー専用のため)
- 復活予定時刻は`NetworkVariable`で同期しており、HUD用に`respawnRemaining`(復活までの残り秒数)を全クライアントで読める
- 変身は死亡時に自動で解除されるため、復活直後は通常状態(再変身のクールタイムは死亡時から数える)
- **復活してから`_invincibleDuration`秒(既定5秒、Inspectorで調整可能)は無敵**。無敵中はモデルが点滅する(点滅は`CS_PlayerVisual`が担当。間隔は`_blinkInterval`、既定0.1秒)
  - 無敵の終了時刻は`NetworkVariable`で同期しており、`isRespawnInvincible`で全クライアントが無敵中かを判定できる(点滅も全クライアントで見える)
- 死亡中の見た目の演出は未実装

## スコア: `CS_PlayerResultDataHolder` / `CS_PlayerScoring`

スコアの仕組み自体(`CS_ResultData`、リザルトへの受け渡し)は[ClaudeDocs/スコアの使い方.md](../ClaudeDocs/スコアの使い方.md)を参照。

- 点数(仕様書「ゲームループ」・データ表)

| できごと | 点数 | 調整項目(`CS_PlayerScoring`) |
|---|---|---|
| 悪人を倒した | +その悪人の撃破スコア × 暗躍ボーナスの倍率 | 撃破スコアは相手の`IDefeatScore`から読む。無ければ`Default Villain Score`(100) |
| 犯罪を完遂された | −20(どのグループの犯罪でも全プレイヤーが減点) | `Crime Completed Penalty` |
| 警察に見つかった | −50(警察が新しく自分を標的にするたび。警察に倒されたこと自体では減点しない) | `Found By Police Penalty` |
| 他プレイヤーを倒した | 0(仕様に点数が無いため。回数は数える) | `Defeat Player Score` |

- 警察に見つかったことは、警察側(`CS_PoliceBrain`)が新しく標的にした瞬間に`CS_PlayerScoring.ReportFoundByPolice()`で知らせてくれる(減点と、暗躍ボーナスのリセットの両方を行う)。複数の警察に見つかると、その人数分減点される
- 誰が倒したかは、攻撃側(`CS_PlayerAttack` / `CS_PlayerSpecialAttack`)が`CS_PlayerScoring.DealDamage`経由でダメージを与え、「当てる前は生きていた相手が、当てた後に倒れたか」で判定する(アイテムなど、これを通らない攻撃で倒した分はスコアに入らない)
- **暗躍ボーナス**: 連続撃破数が`Bonus Start Count`(5)人目から、倍率が`Bonus Step`(0.2)ずつ上がる(4人目まで×1、5人目×1.2、6人目×1.4…)
  - 変身を解く / HPが0になる / 警察に見つかる、のどれかで連続撃破数が0に戻る
- **合計はマイナスにもなる**(0で止めない)。減点(警察に見つかった・犯罪完遂)はそのまま引く。以前は表示の合計(`CS_ResultData.totalScore`)だけ0未満を0にしていたため、犯罪完遂の減点が全員に入って内部の合計がマイナスに溜まると、悪人を倒しても表示が0から動かなかった(Issue #224)
- 点数と回数は`NetworkVariable`で同期(書き込みはサーバーのみ)。各クライアントが受け取って、手元の`CS_ResultData`とスコアUI(`CS_UIScoreModel`、表示先は`playerNumber`)へ反映する
- ゲーム終了時は`CS_PlayerResultDataHolder.CollectResults()`で全プレイヤー分の`CS_ResultData`を集め、`CS_ResultDataStore.Save`に渡す想定
- **他の担当者側の対応が必要なもの**(それまでは該当の処理が動かない)
  - 悪人の種類ごとの撃破スコア: 悪人側が`IDefeatScore`を実装する(未実装の間は全員100点)
  - ゲーム終了時のリザルトへの保存: `CS_TimerController`のTODOを有効にする(シーン移動のネットワーク方針とあわせて)

## アイテムスロット: `CS_PlayerItemSlot`

[ItemSlot実装ガイド](ItemSlot実装ガイド.md)に沿って実装済み。詳細な仕組み(アイテム側の設計、`CSO_ItemDataCarriable`など)はそちらを参照。

- `ICarriableItemHolder`を実装。スロットは1つで、拾えるのは携帯型アイテム(`CSO_ItemDataCarriable`)のみ
- 拾得(`TryStoreItem`)は`CS_ItemBase`側の仕組みにより、常にサーバー(またはオフライン)でのみ呼ばれる
- 使用ボタンで`CSO_ItemDataCarriable.Activate()`を呼び、スロットを空にする。攻撃と同じく「クライアントから依頼 → サーバーで確定」の形(RPC経由)
- `CS_PlayerHealth`は`IHealable`を実装済み(`Heal(amount)`)。回復アイテムはそのまま使える。死亡中は回復しない
- **所持アイテムの同期**: `CSO_ItemDataCarriable`はアセット参照のため、そのままでは`NetworkVariable`に乗らない。そこで`Player`の`CS_PlayerItemSlot`の`Syncable Items`(持てるアイテムの一覧。現在は爆弾・陽動ホログラム・煙幕)の**何番目を持っているか**を`NetworkVariable<int>`で同期し、各クライアントは番号からアセットを引き直している(-1 = 何も持っていない)
  - `heldItem` / `hasItem` / `onItemChanged`は全クライアントで使える(リモートクライアントでもHUDに自分のアイテムが出て、使用ボタンも反応する)。効果の発動はサーバーのみ
  - **新しい携帯型アイテムを追加したら、`Syncable Items`にも登録すること**。未登録のアイテムはホスト・オフラインでは使えるが、リモートクライアントでは「持っていない」扱いになる(拾った時に警告ログが出る)
- 使用ボタン(UseItem)は E / コントローラーRB(仕様書の操作表どおり)。インタラクトは通常攻撃ボタンなので、アイテム使用とは干渉しない

## HUD(UIへの反映): `CS_PlayerHpUI` / `CS_PlayerSpecialGaugeUI` / `CS_PlayerItemSlotUI` / `CS_PlayerRankOverheadUI` / `CS_PlayerWantedLevelUI`

ゲーム側の値をUI側のModel(`ClaudeDocs/UIModelの使い方.md`)へ流すだけのコンポーネント。数値の変更は一切行わない。UI側(`UICanvas`)はプレイヤーのことを知らない。

| コンポーネント | 反映元 | UIのModel | 表示 |
|---|---|---|---|
| `CS_PlayerHpUI` | `CS_PlayerHealth.onHpChanged` | `CS_UIPlayerHpModel` | 自分のHPゲージ |
| `CS_PlayerSpecialGaugeUI` | `CS_PlayerSpecialGauge.onGaugeChanged` | `CS_UISpecialGaugeModel` | 自分の必殺技ゲージ |
| `CS_PlayerItemSlotUI` | `CS_PlayerItemSlot.onItemChanged` | `CS_UIItemSlotModel` | 自分の所持アイテムのアイコン |
| `CS_PlayerRankOverheadUI` | (`CS_Player.playerNumber`とローカルのカメラを渡すだけ) | `CS_UIPlayerRankOverhead`(子の`PlayerRank`) | 他プレイヤーの頭上の順位 |
| `CS_PlayerWantedLevelUI` | `CS_PlayerWantedLevel.onLevelChanged` | `CS_UIWantedLevelModel` | 自分の手配度(星) |

- HP・必殺技ゲージ・手配度: Modelは全クライアントで全プレイヤー分を`CS_Player.playerNumber`で`Bind`し、自分(`CS_Player.isLocalPlayer`)だけがその前に`SetLocalPlayerNumber`で番号を登録する。UI側のPresenterは登録された番号のModelだけを表示するので、画面には自分の分だけが出る
- 手配度: Modelは手配度0で始まるため、作った直後に今の手配度へ合わせる(途中参加など)。星の数は`CS_PlayerWantedLevel.maxLevel`(既定5)
- HP: HP上限だけが変わった時(アイテムによる強化など)は`onHpChanged`が来ないため、`CS_PlayerHpUI`は`CS_PlayerStats.onMaxHpChanged`も受け取ってハートの数を追従させる(Issue #223)
- 必殺技ゲージ: `CS_UISpecialGaugeModel`は上限を後から変えられないため、上限(`maxGauge`)が変わったらModelを作り直す
- アイテムスロット: 画面に1つだけのため、自分(Owner)のプレイヤーだけが`Bind`する。アイコンは`CSO_ItemData.icon`を使う(**アイコン未設定のアイテムは、持っていてもスロットが空の表示になる**。現在は陽動ホログラム・煙幕が未設定)
- 頭上の順位: 他人の頭上に出すUIのため、全クライアントで全プレイヤー分`Bind(playerNumber, カメラ)`する(使い方は[ClaudeDocs/頭上順位UIの使い方.md](../ClaudeDocs/頭上順位UIの使い方.md))
  - カメラは、どのプレイヤーの分にも**ローカルプレイヤーのカメラ**(`CS_Player.playerCamera`)を渡す。他人のプレイヤーのカメラは無効化されているため
  - 他人のプレイヤーが先にスポーンした場合はまだローカルのカメラが無いので、ローカルプレイヤーのスポーン時に、出現中の全プレイヤー分をBindし直す
  - 自分の頭上はUI側が自動で隠す。順位は`CS_UIScoreModel`(スコアは`CS_PlayerResultDataHolder`が反映済み)から計算される
- オフラインのテストシーンでも動く(自分のプレイヤー扱い、`playerNumber`は0)。そのため`CS_PlayerSpecialGauge`はオフライン時も`onGaugeChanged`を発生させる

## 当たり判定の共通処理: `CS_AttackHitDetector`

通常攻撃・必殺技どちらの判定も[`CS_AttackHitDetector.FindTargets()`](../Assets/Programmer/Script/Combat/CS_AttackHitDetector.cs)(static)を使っている。新しい攻撃手段(敵の攻撃など)を作る場合もこれを再利用できる。

`PlayerControls.inputactions`(`Assets/Programmer/InputAction/`)で定義。`Generate C# Class`が有効になっており、`Assets/Programmer/Script/Input/CustomInputAction.cs`に自動生成される。**このアセットを編集した場合、生成先のファイルを直接編集しないこと**(再生成で上書きされる)。

**RT+LT同時押し(必殺技)の実装について**: ゲームパッドの`Attack`と`Special`は両方ともRTを使うため、`Special`アクションはInput Systemの`OneModifier`コンポジット(LTを押しながらRT)で組んでいる。ただし`Attack`アクション自体は素のRTに直接割り当てているため、RT+LTを同時に押すと`Attack`と`Special`の両方が反応してしまう。これを防ぐため、LT単体を読むだけの`SpecialModifier`アクションを追加し、`CS_PlayerAttack`側で「LTが押されている間は攻撃ボタンを無視する」ようにしている(`CS_Player.isSpecialModifierHeld`)。

## ネットワークの考え方

- `CS_Player`の移動・ジャンプ・ダッシュは、操作しているクライアント(Owner)側でRigidbody物理を直接動かし、`NetworkTransform`(Authority Mode: `Owner`)が結果を他クライアントへ同期する
- ステータスの変更(`CS_PlayerStats`の`SetXxx`系)、HP・ゲージの増減、攻撃判定の確定は**すべてサーバー側で行う**(`NetworkVariable`はサーバーのみ書き込み可、攻撃判定はRPC経由でサーバーに判定を依頼する)
- オフライン(`NetworkManager`が動いていない)のテストシーンでも単体で動作するように、各コンポーネントは`IsSpawned`で分岐している(動作確認用シーン: `Assets/Programmer/Scene/Test/ObjectTest/PlayerTest.unity`)

## 見た目(仮アセット)

- 現在は`Mannequin_Medium.fbx`+仮のAnimator Controllerを`Player`の子`Model`として表示している(Editorツール`Tools/Player/仮の見た目を組み込む`で生成)
- ゲームロジックは見た目を知らない。`CS_PlayerVisual`が状態・イベントを見てAnimatorへ反映する
- 通信: 移動・接地・死亡・被弾は各クライアントが同期済みの状態から自前で計算。ジャンプ・ダッシュ・攻撃・必殺技は操作している本人が再生しつつRPC(`SendTo.NotMe`)で他クライアントへ通知(`NetworkAnimator`は不使用)
- 差し替え手順・パラメータ一覧: [プレイヤー見た目の差し替えガイド.md](プレイヤー見た目の差し替えガイド.md)
- アイテム使用のモーションは未対応(所持アイテムは全クライアントで分かるようになったため、`CS_PlayerItemSlot`に使用時のイベントを足せば対応できる)

## 現状未実装・既知の注意点

- **アイテムスロットの同期**: 番号で同期しているため、新しい携帯型アイテムは`Syncable Items`への登録が必要(上記「アイテムスロット」参照)
- **インタラクト機能**: `CS_PlayerInteractor`(中出さん作)が、通常攻撃ボタン(左クリック / RT)の長押しで近くの操作できるもの(`IInteractable`。現状はケアパッケージ)を操作する。操作できるものの近くでは通常攻撃は出ない
- **死亡・復活の演出**: 10秒後にその場で復活し、復活直後の無敵中は点滅するが、死亡中の見た目の変化やエフェクトはない
- **長押しジャンプ**: 「スタイリッシュかも」という案があるが未着手(通常ジャンプのみ実装)
- チーム分け・フレンドリーファイアのON/OFF切り替えは意図的に実装していない(常時フレンドリーファイア有効という仕様のため)
