# デザイナー作業フロー(作業 → push まで)

デザイナーは **Unity を開かずに**、GitHub Desktop の操作だけで素材をゲームに取り込めます。
やることは「決まった場所にファイルを置く → `designer_develop` ブランチで commit → push」だけです。

```
【進捗】 Artist/ に作業データを置く ──→ commit & push ──→ Discord「📝 作業進捗」
【完成】 Assets/Designer/ に書き出す ─→ commit & push ──→（自動で Unity に取り込み）──→ Discord「✅ 作業完了」
```

---

## 0. 最初に1回だけやること

1. GitHub Desktop でリポジトリ `DA-Yoshi-KYO/MS2027Project` をクローンする
   - 「Git LFS を初期化しますか？」と聞かれたら **Initialize Git LFS** を押す
2. クローンしたフォルダの `Tools/SetupGitHooks.bat` をダブルクリックする
   - `[OK] Git hooks enabled` と出れば完了(ロック機能とコミットメッセージのチェックが有効になります)

---

## 1. 作業するブランチ

**必ず `designer_develop` ブランチで作業します。**

1. GitHub Desktop 上部の **Current branch** をクリック
2. `designer_develop` を選ぶ
3. 作業を始める前に **Fetch origin → Pull origin** で最新にする

> ⚠ `develop` や `main`、自分の名前のブランチには push しないでください。
> `designer_develop` 以外に push した素材は Unity への自動取り込みが行われません。

---

## 2. 作業場所

リポジトリのフォルダ内の、次の2か所だけを使います。

| 場所 | 置くもの | 例 | push したときの扱い |
|---|---|---|---|
| `Artist/` | **作業中のデータ**(元データ) | `.mb` `.ma` `.psd` `.spp` など | 📝 作業進捗 |
| `Assets/Designer/` | **完成して書き出したデータ**(ゲームで使うもの) | `.fbx` `.png` など | ✅ 作業完了(Unity に自動取り込み) |

- `Artist/` も `Assets/Designer/` も、中に**自由にフォルダを作って構いません**
  - 例: `Artist/Chara/Hero/hero.mb`、`Assets/Designer/Chara/Hero/hero.fbx`
  - 新しいフォルダの `.meta` も自動で作られます
- 空のフォルダは push されません(中にファイルを入れてから push してください)
- `Assets/Designer/` のフォルダ構成は、**最初に完成の push をする前に決めておく**のがおすすめです(後から移動すると参照が外れます。「4. 完成の push」の注意を参照)
- `.meta` ファイルは**作らない・触らない**でください(自動で作られます)

---

## 3. 進捗の push(作業途中を共有する)

作業途中のデータを保存・共有したいときに行います。**何回やっても大丈夫です。**

1. 作業データを `Artist/` 以下に保存する
2. GitHub Desktop の左下にコミットメッセージを書く
   - 先頭に **prefix(`update:` など)が必須**です(下の表を参照)
   - 例: `update: 主人公モデルの顔を作成中`
3. **Commit to designer_develop** を押す
4. 上部の **Push origin** を押す

→ Discord のデザイナー進捗チャンネルに **「📝 作業進捗」** が届きます。

---

## 4. 完成の push(ゲームに取り込む)

素材が完成して、ゲームで使える状態になったら行います。

1. Maya などから、ゲーム用のデータを `Assets/Designer/` の該当フォルダに書き出す
   - **新しい素材**: 名前を付けてそのまま書き出す
   - **既存の素材を直す**: **同じ名前で上書き**する
2. コミットメッセージを書く(例: `feat: 主人公モデルを追加`)
3. **Commit to designer_develop** → **Push origin**

→ push 後は自動で処理されます(あなたの操作は不要です)。

1. 素材が Unity 用のブランチ(`designer_output`)にコピーされる
2. 新しい素材があれば、Unity が自動で取り込み(`.meta` を作成)
3. 終わると Discord に **「✅ 作業完了」** が届く(担当者にメンションが付きます)

- 新しい素材を含む場合は **完了まで数分〜10分程度** かかります。上書きだけなら1分程度です。
- 取り込まれた素材は、管理者が本流(`develop`)に反映します。

> ⚠ **ファイル名の変更・移動はしないでください。** Unity 上で別の素材扱いになり、配置済みの参照が外れます。
> 変更が必要な場合はプログラマーに相談してください。

---

## 5. コミットメッセージの prefix

コミットメッセージの先頭には、次のどれかを付けます(付けないとコミットできません)。

| prefix | 使いどころ |
|---|---|
| `feat:` | 新しい素材を追加した |
| `update:` | 作業途中の保存・既存素材の調整 |
| `fix:` | 素材の不具合を直した |
| `chore:` | その他(整理・削除など) |

---

## 6. ファイルのロック(担当者以外は編集できません)

`.mb` `.fbx` `.abc` は、**最初にコミットした人がそのファイルの担当者**になり、他の人は編集できなくなります。

- 他の人が担当するファイルは読み取り専用になっています
- 他の人の担当ファイルを変更してコミットしようとすると、次のエラーが出ます

```
エラー: ロック中のファイルが含まれています。

  Artist/Chara/Hero/hero.mb は ○○ によってロックされています

このファイルは作成者以外編集できません。担当を変更する場合は管理者に連絡してください。
```

→ 変更を取り消す(GitHub Desktop でファイルを右クリック → **Discard changes**)か、担当の引き継ぎを管理者に依頼してください。

---

## 7. 困ったとき

| 症状 | 対処 |
|---|---|
| コミット時に「コミットメッセージにprefixがありません」 | メッセージの先頭に `update:` などを付ける |
| コミット時に「ロック中のファイルが含まれています」 | 上の「6. ファイルのロック」を参照 |
| コミット時に「ロック情報を取得できませんでした」 | インターネット接続を確認して再度コミット |
| Push 時に「newer commits」などで失敗する | **Pull origin** してから、もう一度 **Push origin** |
| 「✅ 作業完了」が届かない | `Assets/Designer/` 以外に置いていないか確認。上書き前と全く同じ内容の場合も届きません。それでも来なければプログラマーに連絡 |
| 置いたはずの素材がゲームに出てこない | 管理者が `develop` に反映するまでは出てきません |
