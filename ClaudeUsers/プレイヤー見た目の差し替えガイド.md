# プレイヤーの見た目の差し替えガイド

プレイヤーの見た目(モデル・アニメーション)は、ゲームロジックから完全に分離されています。本番アセットが来たら、以下の手順で差し替えられます。**C#の変更は基本的に不要**です。

## 仕組み

```
CS_Player / CS_PlayerAttack / CS_PlayerSpecialAttack / CS_PlayerHealth
        │ 状態(isGrounded, isDead …)とイベント(onJumped, onStepStarted …)
        ▼
CS_PlayerVisual ── Animatorのパラメータを更新 ──▶ Animator Controller ──▶ モデル
```

- ゲームロジック側は`CS_PlayerVisual`を知らない(外してもゲームは動く)
- `CS_PlayerVisual`はAnimatorを子オブジェクトから自動で探す(`_animator`が空でも可)
- Animator Controllerに**存在しないパラメータは無視される**。全部揃っていなくてよい
- 見た目は子の`Model`(`CS_PlayerVisual`の`Animator`欄)の1つだけ。常時変身(Issue #277)になったため、以前あった通常の見た目との切り替えと、変身途中のエフェクトは削除した
  - 現在のモデル: Munnki(`Assets/Programmer/PlaceholderAsset/Player/Munnki/Model/FBX/Munkki_mixamo_rigged.fbx`)
    - Rigは**Humanoid**(Mixamoのボーン。Humanoidのモーションならそのまま使い回せる)
    - 大きさは当たり判定のカプセル(高さ2m)に合わせ、`Model`のScaleを約1.3倍(元は約1.54m)にしている
    - 足元を合わせるため、`Model`のローカルYは約-0.864(靴底がモデルの原点より約0.1m(拡大後は約0.136m)下にあるため)
    - マテリアルは`Munnki/Model/Material/`(HDRP/Lit)。FBXのマテリアル設定(Remap)で割り当てている
  - Animator Controller: `Munnki/Animation/PlayerMunnkiAnimator.controller`(以前の仮Controllerを複製して、**モーションだけ空にしたもの**)

## モーションの追加・差し替え手順(Munnki)

アニメーションは**ツールで組み込みます**。Controllerを手で編集しても、ツールを実行すると作り直されるので注意。

1. モーションのFBXを`Assets/Programmer/PlaceholderAsset/Player/Munnki/Animation 1/`に入れる(Mixamoから落とす場合は「Without Skin」でよい。Rigなどの読み込み設定はツールが行う)
2. [`CSED_PlayerAnimatorBuilder.cs`](../Assets/Editor/Player/CSED_PlayerAnimatorBuilder.cs)の上の方にある「どの動作にどのアニメーションを使うか」の表で、動作ごとにFBXのファイル名(拡張子なし)を書く
   - 同じファイル名で上書きしただけなら、表はそのままでよい
   - モーションの前後に余計な動きがある場合は`start` / `end`(0〜1)で使う範囲を切り出す(ジャンプは1つのFBXを踏み切り・空中・着地に切り出している)
   - 攻撃系は`impact`(0〜1)に、モーションの中で当たる瞬間(振り抜く瞬間)の位置を書く。ツールが判定のタイミングに合わせる(下の「タイミングの合わせ方」)
3. `Tools/Player/アニメーションを組み込む`を実行する

ツールがやること:
- FBXをHumanoidで読み込み、ループ・切り出しを設定する(アニメーションのFBXはMunnkiとボーンの並びが少し違うため、それぞれのFBXからAvatarを作る)
  - Mixamoの「Without Skin」のFBXは基準の姿勢(T-ポーズ)を持っていない。そのままだとモーションの最初の姿勢(走りなら膝を曲げた姿勢)が基準になり、**足が変な方向に曲がる**。そのため、ボーンの割り当てと基準の姿勢はMunnkiのモデルのものを写している(手でAvatarを作り直す場合も、基準の姿勢をT-ポーズにすること)
- `Munnki/Animation/PlayerMunnkiAnimator.controller`を作り直し、`Player.prefab`の`Model`のAnimatorに設定する
- 攻撃・必殺技・ダッシュ・パリーは、ゲーム側の時間(`CSO_AttackData`の`Duration`、`CS_Player`の`Dash Duration`、表の下の`_parryDuration`)に収まるよう再生速度を決める(`impact`がある時は、下の「タイミングの合わせ方」で決める)

| 動作 | 今のモーション |
|---|---|
| 待機 | `Standing Idle` |
| 通常の移動 | `Standard Walk`(`Locomotion`。前後左右すべて) |
| 走り(ダッシュ中・ダッシュボタンを押し続けている間) | `Running`(`Sprint`。前後左右すべて) |
| ジャンプ(踏み切り・空中・着地) | `Jumping`を3つに切り出し(以前の`Jump`は使っていない) |
| ダッシュ | **無い**(状態を作らない。移動のモーションのまま) |
| 通常攻撃1〜3段目 | `Attack1`〜`Attack3`(4・5段目は、タイミングが同じ2段目・3段目のモーションを使う) |
| 必殺技 | `SpecialAttack` |
| パリー(反撃) | `parry` |
| 奇襲 | `Surprise Uppercut` |
| 被弾 | **無い**(状態を作らない) |
| 死亡 | `defense`(最後の姿勢のまま、復活するまで止まる) |

## タイミングの合わせ方(ツールが自動で行う)

| 動作 | 合わせ方 |
|---|---|
| ジャンプ | 踏み切りは**沈み込みの一番下(11フレーム)から最高点(22)まで**。ボタンを押した瞬間に体が浮くため、しゃがむ構え(0〜10)は使わない。空中は最高点から着地の直前(22〜31)で、ループせず最後の姿勢のまま着地を待つ。着地は33〜51。踏み切り・空中は、ジャンプ力÷重力(今は5÷9.81 ≒ 0.51秒)で再生する。**移動しながら着地した時は、着地の動きを待たずに移動へ戻る**(`Speed`が0.3より大きい時) |
| 通常攻撃・必殺技 | 表の`impact`(当たる瞬間)が、`CSO_AttackData`の`Hit Delay`ちょうどに来るよう、再生速度と使う範囲を計算する。はみ出す側(構え、または戻り)は切り詰める |
| 奇襲 | 飛び込みを始めた瞬間に構えから再生し、**アッパーが当たる瞬間に打撃が来る**よう、飛び込む距離から速さ(`AmbushSpeed`)をゲーム中に決める(`CS_PlayerVisual`。速さは0.3〜6倍に制限)。ツールは、クリップの頭から当たる瞬間までの秒数を`CS_PlayerVisual`の`Ambush Impact Time`へ書き込む |
| 5段コンボの4・5段目 | `Hit Delay`・`Duration`が一番近い段のモーションを使う(今は4段目→2段目、5段目→3段目のモーション)。`CS_PlayerVisual`の`Attack Motion For Step`へ書き込む |

- 当たる瞬間(`impact`)は、FBXのアニメーションで動きが一番速いフレームを目安にした(Attack1: 27/69、Attack2: 37/89、Attack3: 53/98、必殺技: 33/95、奇襲: 32/105)。見た目がずれていたら表の`impact`を直して実行し直す
- ジャンプの区切り(11 / 22 / 33 / 51)は、`Jumping`の腰の高さの動きから読み取った。モーションを替えたら表の`start` / `end`も直す

※ Humanoidはモーションが空だと腰がモデルの原点(足元)まで下がり、地面にめり込む。表で待機を`null`にした時は、仮の立ちポーズ(`Munnki_TPose.anim`)を使う
※ ツールはControllerのファイルを消さずに中身だけ作り直す(消して作り直すと、読み込み済みの`Player.prefab`がControllerを見失い、プレイしてもアニメーションしなくなる)
※ モーションを入れた後、足が地面から浮いたりめり込んだりしていたら、`Player.prefab`の`Model`のローカルYで合わせる

## Animatorパラメータ(コードとの約束)

定義: [`CS_PlayerAnimatorParams.cs`](../Assets/Programmer/Script/Entity/Player/CS_PlayerAnimatorParams.cs)

| 名前 | 型 | 内容 |
|---|---|---|
| `Speed` | float 0〜1 | 移動の速さ(通常移動速度で割った値) |
| `MoveX` | float -1〜1 | 体から見た左右の移動(右が+) |
| `MoveZ` | float -1〜1 | 体から見た前後の移動(前が+) |
| `Grounded` | bool | 接地しているか |
| `Dead` | bool | 死亡中か |
| `Sprint` | bool | 通常の移動より速く動いているか(ダッシュ中・ダッシュボタンを押し続けている間)。座標の変化の速さが、通常の移動の速さと走る速さの中間より速いとtrue |
| `Jump` | trigger | ジャンプした瞬間 |
| `Dash` | trigger | ダッシュ開始の瞬間 |
| `Attack` | trigger | 通常攻撃の各段の開始(直前に`ComboStep`がセットされる) |
| `ComboStep` | int | 何段目か(0始まり) |
| `Special` | trigger | 必殺技の開始 |
| `Hit` | trigger | HPが減った(死亡時を除く) |
| `Parry` | trigger | パリー(反撃)が決まった(全クライアントで発生) |
| `Ambush` | trigger | 奇襲の飛び込みを始めた |
| `AttackSpeed` | float | 通常攻撃のモーション速度の倍率(暗躍ボーナスで上がる。1で等倍) |
| `AmbushSpeed` | float | 奇襲のモーション速度の倍率(当たる瞬間に打撃が来るよう、飛び込みを始めた時に決める) |

## 差し替え手順

1. 新しいモデルをインポートする(Humanoidを推奨。アニメーションを使い回せる)
2. `Player.prefab`を開き、子の`Model`を新しいモデルのプレハブに入れ替える
   - 足元がカプセルの底(ローカルY = -1)に来るようにする
   - モデルに`Animator`が付いていること
3. 新しいAnimator Controllerを作り、上の表のパラメータで遷移を組む(既存の`PlayerMunnkiAnimator.controller`を複製して、モーションだけ差し替えるのが早い)
4. `Model`の`Animator`にControllerを割り当てる
5. `CS_PlayerVisual`の`Animator`欄が新しい`Model`のAnimatorを指しているか確認(自動検索されるので空でも可)
6. モデルを変えたら、`CSED_PlayerAnimatorBuilder`のモデルのパス(`_modelPath`)も合わせる(以前のMannequin用の組み込みツール`CSED_PlayerTempVisualBuilder`は、このツールに置き換えて削除した)

## 注意点

- **ルートモーションは使わない**(移動はRigidbodyが行う。`CS_PlayerVisual`が強制的にオフにする)
- 攻撃の長さ・判定タイミングは`CSO_AttackData`(`Duration`、`Hit Delay`)が決める。モーション側をそれに合わせる(`Tools/Player/アニメーションを組み込む`が再生速度をDurationに合わせる)。段数を増やす場合は`Attack Steps`と`ComboStep`の遷移を増やす
- 攻撃・ジャンプ・ダッシュ・必殺技の再生は「操作している本人が再生+RPCで他クライアントへ通知」。途中参加のクライアントには過去の単発動作は再生されない(死亡は状態から判定するので反映される)
- アイテム使用のモーションは未対応(`CS_PlayerItemSlot`の所持状態がサーバー側にしかないため。対応するときはスロットの同期とセットで行う)
- 新しい動作(例: しゃがみ)を足すときは、ゲームロジック側にイベントを追加し、`CS_PlayerVisual`の`ActionType`とパラメータを増やす
